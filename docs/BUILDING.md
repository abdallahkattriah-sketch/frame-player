# Building and releasing

## Build

```powershell
npm run setup:mpv        # once: the mpv build that gets bundled
npm run dist             # installer + portable exe in release/
npm run pack             # faster: unpacked app only (release/win-unpacked)
```

`npm run dist` collects third-party licenses (`scripts/build/collect-licenses.mjs`), builds
with electron-vite, then packages with electron-builder (`electron-builder.yml`):

| Output                                 |                                                                |
| -------------------------------------- | -------------------------------------------------------------- |
| `release/Frame-Setup-<version>.exe`    | NSIS installer, per-user, choice of folder (≈150 MB)           |
| `release/Frame-<version>-portable.exe` | Portable single file; data in `Frame Data` beside it (≈150 MB) |
| `release/win-unpacked/`                | The app folder both are made from (≈450 MB)                    |

What is packaged:

- `out/` and the runtime dependencies (`zod`, `koffi` + its Windows binary, unpacked from the
  asar archive) in `app.asar`
- `resources/mpv/`: `mpv.exe`, `d3dcompiler_43.dll`, `mpv/fonts.conf` only
- `resources/licenses/`: Frame's license, third-party notices and license texts, mpv's
  license files
- Electron fuses: no `ELECTRON_RUN_AS_NODE`, no `NODE_OPTIONS`, no `--inspect`, asar integrity
  validation, app loaded only from the asar, encrypted cookies
- Chromium UI languages limited to English and Arabic

The app icon is generated by `node scripts/build/make-icon.mjs` (`build/icon.png`).

## Verify a build

```powershell
node scripts/build/smoke-test.mjs                                  # release/win-unpacked
node scripts/build/smoke-test.mjs release\Frame-<version>-portable.exe
```

The smoke test launches the packaged app with a test video and a temporary data folder, then
checks that the bundled mpv plays (time advances, via mpv's own IPC), that both windows loaded
from the package (development switches ignored), that `%APPDATA%\Frame` was not touched, and
that mpv exits with Frame.

Before publishing, also install with the installer on a clean Windows account, play a file,
and uninstall.

## Release process

1. Update `version` in `package.json` (semantic versioning).
2. Run the full checks: `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:e2e`.
3. `npm run dist`, then the smoke test on both outputs.
4. Tag the commit `v<version>`; publish the two `.exe` files with their SHA-256 hashes.
5. **mpv source (GPL):** when distributing publicly, also provide the corresponding source of
   the bundled mpv build (see THIRD_PARTY_NOTICES.md): either host the mpv source at the
   bundled commit and the shinchiro build release alongside your download, or include a
   written offer.

## Code signing

Builds are **not signed**. Unsigned installers trigger Windows SmartScreen warnings until they
gain reputation. To sign, obtain an Authenticode certificate (OV/EV, or a cloud signing service
such as Azure Trusted Signing) and configure electron-builder's `win.signtoolOptions` or
`win.azureSignOptions` with credentials from environment variables in CI — never in the
repository. Signing applies to `Frame.exe`, the installer, the uninstaller and `mpv.exe`.

## Known build notes

- `npm audit` reports a moderate issue in `sprintf-js`, used by electron-builder's download
  helper at build time only; it is not part of the shipped app.
- electron-builder downloads Electron, NSIS and related tools from GitHub on the first build.
